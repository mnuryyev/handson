Процесс - это запущенная программа в памяти. У каждого процесса есть уникальный идентификатор (PID), родитель, ресурсы и состояние. Управление процессами - одна из ключевых задач системного администратора.

---

## Что такое процесс

При запуске программы ядро создаёт процесс и выделяет ему:

- **PID** - уникальный числовой идентификатор
- **PPID** - PID родительского процесса
- **UID / GID** - от чьего имени запущен
- **Виртуальную память** - адресное пространство
- **Файловые дескрипторы** - открытые файлы и сокеты
- **Приоритет** - nice value, влияет на распределение CPU

```bash
# Каждый процесс рождается через fork() + exec()
# init/systemd (PID 1) - прародитель всех процессов

pstree -p              # дерево процессов с PID
pstree -p | head -20
```

## Состояния процессов

| Символ | Состояние | Описание |
|--------|-----------|----------|
| `R` | Running | Выполняется или готов к выполнению |
| `S` | Sleeping | Ждёт события (прерываемый сон) |
| `D` | Disk sleep | Ждёт I/O (непрерываемый — нельзя убить) |
| `Z` | Zombie | Завершился, но родитель не прочитал статус |
| `T` | Stopped | Остановлен сигналом (SIGSTOP / SIGTSTP) |
| `I` | Idle | Простаивает (ядерные потоки) |
| `<` | — | Высокий приоритет (отрицательный nice) |
| `N` | — | Низкий приоритет (положительный nice) |
| `s` | — | Лидер сессии |
| `l` | — | Многопоточный |
| `+` | — | Процесс на переднем плане |

## ps - снимок процессов

`ps` (process snapshot) - показывает процессы в момент вызова.

### Основные варианты

```bash
ps                     # процессы текущего терминала
ps aux                 # все процессы, все пользователи (BSD-стиль)
ps -ef                 # все процессы с PPID (UNIX-стиль)
ps -ejH                # дерево процессов
ps -u alice            # процессы пользователя alice
ps -p 1234             # конкретный PID
```

### Расшифровка `ps aux`

```bash
ps aux
# USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root         1  0.0  0.1 168940 13208 ?        Ss   Mar01   0:05 /sbin/init
# alice     1234  2.3  1.5 512340 61440 pts/0    Sl+  10:22   0:12 python3 app.py
```

| Колонка | Описание |
|---------|----------|
| `USER` | Владелец процесса |
| `PID` | ID процесса |
| `%CPU` | Использование CPU (%) |
| `%MEM` | Использование RAM (%) |
| `VSZ` | Виртуальная память (KB) |
| `RSS` | Реальная память в RAM (KB) |
| `TTY` | Терминал (`?` = нет терминала, демон) |
| `STAT` | Состояние процесса |
| `START` | Время запуска |
| `TIME` | Суммарное время CPU |
| `COMMAND` | Команда запуска |

### Полезные фильтры

```bash
# Найти процесс по имени
ps aux | grep nginx
ps aux | grep -v grep | grep nginx   # без строки самого grep

# Красиво с заголовком
ps aux | head -1; ps aux | grep nginx

# Только PID процессов
ps -C nginx -o pid=

# Кастомный вывод
ps -eo pid,ppid,user,stat,pcpu,pmem,comm --sort=-pcpu | head -20

# Процессы с деревом
ps -ejH | grep -A5 nginx
```

### Кастомные поля для `-o`

```bash
ps -eo pid,ppid,user,stat,ni,pcpu,pmem,vsz,rss,etime,comm
#         │    │     │   │   │    │    │   │   │      └── имя команды
#         │    │     │   │   │    │    │   │   └───────── время работы
#         │    │     │   │   │    │    │   └───────────── RSS память
#         │    │     │   │   │    │    └───────────────── виртуальная память
#         │    │     │   │   │    └────────────────────── % памяти
#         │    │     │   │   └─────────────────────────── % CPU
#         │    │     │   └─────────────────────────────── nice value
#         │    │     └─────────────────────────────────── состояние
#         │    └───────────────────────────────────────── пользователь
#         └────────────────────────────────────────────── PPID
```

## top - интерактивный мониторинг

`top` показывает процессы в реальном времени и обновляется каждые 3 секунды.

```bash
top              # запустить
top -u alice     # только процессы alice
top -p 1234      # следить за конкретным PID
top -b -n 1      # batch-режим, один снимок (для скриптов)
top -b -n 1 > processes.txt  # сохранить в файл
```

### Заголовок top

```
top - 14:32:01 up 5 days, 3:12,  2 users,  load average: 0.52, 0.48, 0.41
Tasks: 187 total,   1 running, 186 sleeping,   0 stopped,   0 zombie
%Cpu(s):  3.2 us,  0.8 sy,  0.0 ni, 95.5 id,  0.3 wa,  0.0 hi,  0.2 si
MiB Mem :   7854.3 total,   1203.5 free,   3841.2 used,   2809.6 buff/cache
MiB Swap:   2048.0 total,   2001.3 free,     46.7 used.   3712.4 avail Mem
```

| Поле | Описание |
|------|----------|
| `load average` | Средняя нагрузка за 1/5/15 минут |
| `us` | User — процессы пользователей |
| `sy` | System — ядро |
| `ni` | Nice — процессы с изменённым приоритетом |
| `id` | Idle — простой |
| `wa` | Wait — ожидание I/O |
| `hi` | Hardware IRQ |
| `si` | Software IRQ |
| `buff/cache` | Кэш файловой системы (переиспользуется) |

### Горячие клавиши в top

| Клавиша | Действие |
|---------|----------|
| `q` | Выйти |
| `h` | Помощь |
| `k` | Отправить сигнал (kill) процессу |
| `r` | Изменить приоритет (renice) |
| `u` | Фильтр по пользователю |
| `M` | Сортировать по памяти |
| `P` | Сортировать по CPU |
| `T` | Сортировать по времени |
| `1` | Показать каждый CPU отдельно |
| `c` | Показать полную команду |
| `i` | Скрыть простаивающие процессы |
| `f` | Выбрать отображаемые поля |
| `W` | Сохранить настройки |
| `Space` | Обновить немедленно |

## htop - улучшенный top

`htop` - интерактивный мониторинг с цветами, деревом процессов и мышью.

```bash
# Установка
apt install htop      # Debian/Ubuntu
yum install htop      # RHEL/CentOS

htop                  # запустить
htop -u alice         # процессы alice
htop -p 1234,5678     # конкретные PID
htop -d 10            # обновление каждые 10 секунд (десятые доли)
```

### Горячие клавиши в htop

| Клавиша | Действие |
|---------|----------|
| `F1` | Помощь |
| `F2` | Настройки |
| `F3` / `/` | Поиск процесса |
| `F4` | Фильтр |
| `F5` | Переключить дерево/список |
| `F6` | Сортировка |
| `F7` / `F8` | Уменьшить/увеличить nice |
| `F9` | Kill — отправить сигнал |
| `F10` | Выйти |
| `Space` | Отметить процесс |
| `U` | Снять все отметки |
| `t` | Дерево процессов |
| `H` | Скрыть/показать потоки |
| `K` | Скрыть/показать ядерные потоки |
| `u` | Фильтр по пользователю |
| `I` | Инвертировать сортировку |
| `+` / `-` | Раскрыть/свернуть дерево |

## Сигналы

Сигнал - это асинхронное уведомление процессу. Ядро доставляет сигналы мгновенно.

### Основные сигналы

| Номер | Имя | Описание | Можно поймать? |
|-------|-----|----------|----------------|
| `1` | `SIGHUP` | Hang Up — перечитать конфиг | ✅ Да |
| `2` | `SIGINT` | Interrupt — как Ctrl+C | ✅ Да |
| `3` | `SIGQUIT` | Quit — как Ctrl+\ (с core dump) | ✅ Да |
| `9` | `SIGKILL` | Kill — немедленное уничтожение | ❌ Нет |
| `10` | `SIGUSR1` | Пользовательский сигнал 1 | ✅ Да |
| `12` | `SIGUSR2` | Пользовательский сигнал 2 | ✅ Да |
| `15` | `SIGTERM` | Terminate — мягкое завершение | ✅ Да |
| `17` | `SIGCHLD` | Child — дочерний завершился | ✅ Да |
| `18` | `SIGCONT` | Continue — продолжить после STOP | ✅ Да |
| `19` | `SIGSTOP` | Stop — заморозить процесс | ❌ Нет |
| `20` | `SIGTSTP` | Terminal Stop — как Ctrl+Z | ✅ Да |

```bash
# Посмотреть все сигналы
kill -l
# 1) SIGHUP  2) SIGINT  3) SIGQUIT  4) SIGILL ...
```

## kill - отправка сигналов

Несмотря на название, `kill` отправляет **любой сигнал**, не только на завершение.

```bash
# Синтаксис: kill [-сигнал] PID

kill 1234              # отправить SIGTERM (по умолчанию)
kill -15 1234          # SIGTERM — попросить завершиться
kill -9 1234           # SIGKILL — убить немедленно
kill -1 1234           # SIGHUP — перечитать конфиг
kill -STOP 1234        # заморозить процесс
kill -CONT 1234        # разморозить процесс

# По имени (убить все процессы с этим именем)
killall nginx          # всем процессам nginx отправить SIGTERM
killall -9 nginx       # SIGKILL всем nginx
killall -HUP nginx     # перезагрузить конфиг nginx

# pkill — убить по паттерну имени
pkill nginx            # как killall
pkill -u alice         # все процессы пользователя alice
pkill -f "python3 app" # по полной командной строке

# Отправить сигнал группе процессов (минус перед PID)
kill -TERM -1234       # всей группе процессов
```

### Правильный порядок завершения

```bash
# 1. Сначала SIGTERM — дать шанс завершиться корректно
kill -15 $PID

# 2. Подождать
sleep 5

# 3. Проверить, жив ли процесс
kill -0 $PID 2>/dev/null && echo "still alive"

# 4. Если жив — SIGKILL
kill -9 $PID
```

```bash
# Скрипт для корректного завершения
graceful_kill() {
    local pid=$1
    kill -TERM $pid 2>/dev/null
    for i in $(seq 1 10); do
        kill -0 $pid 2>/dev/null || return 0
        sleep 1
    done
    kill -KILL $pid 2>/dev/null
}
```

## Фоновые процессы и управление заданиями

### Запуск в фоне

```bash
command &              # запустить в фоне
nohup command &        # запустить, игнорируя SIGHUP (не умрёт при выходе из терминала)
nohup command > out.log 2>&1 &  # с перенаправлением вывода

# disown — отвязать от терминала после запуска
long_running_command &
disown %1              # отвязать последнее фоновое задание
```

### jobs - управление заданиями

```bash
jobs                   # список фоновых заданий
jobs -l                # с PID

# [1]+ Running    sleep 100 &
# [2]- Stopped    vim file.txt

fg                     # перевести последнее задание на передний план
fg %1                  # перевести задание №1
bg                     # продолжить остановленное в фоне
bg %2                  # задание №2 в фон

# Ctrl+Z — остановить текущий процесс (SIGTSTP)
# Ctrl+C — завершить текущий процесс (SIGINT)
```

## Приоритеты процессов (nice / renice)

`nice` - значение от `-20` (высший приоритет) до `+19` (низший). По умолчанию `0`.

```bash
# Запустить с низким приоритетом
nice -n 10 ./heavy_script.sh     # nice value = 10
nice -n 19 make -j8              # максимально низкий (не мешать системе)

# Повысить приоритет (только root)
nice -n -10 ./critical.sh        # отрицательный nice = выше приоритет

# Изменить приоритет запущенного процесса
renice +5 -p 1234                # понизить для PID 1234
renice -5 -p 1234                # повысить (только root)
renice +10 -u alice              # все процессы alice
renice +10 -g developers         # все процессы группы

# Посмотреть nice в ps
ps -eo pid,ni,comm | head -20
```

## /proc и информация о процессах

```bash
# Каждый процесс имеет директорию /proc/PID/
ls /proc/1234/
# cmdline  cwd  environ  exe  fd  maps  mem  net  stat  status  ...

cat /proc/1234/cmdline    # командная строка (разделитель \0)
cat /proc/1234/status     # подробный статус
cat /proc/1234/environ    # переменные окружения
ls -la /proc/1234/exe     # симлинк на исполняемый файл
ls -la /proc/1234/cwd     # текущая директория процесса
ls /proc/1234/fd/         # открытые файловые дескрипторы

# Сколько файлов открыто у процесса?
ls /proc/1234/fd/ | wc -l

# Лимит открытых файлов
cat /proc/1234/limits
```

## lsof - открытые файлы и сокеты

```bash
lsof                          # все открытые файлы (много)
lsof -p 1234                  # файлы процесса 1234
lsof -u alice                 # файлы пользователя alice
lsof /var/log/syslog          # кто держит файл открытым
lsof -i                       # все сетевые соединения
lsof -i :80                   # кто слушает порт 80
lsof -i :80 -i :443           # порты 80 и 443
lsof -i TCP:22                # TCP соединения на порту 22
lsof -i UDP                   # все UDP соединения

# Найти процесс, занимающий порт
lsof -i :8080 | grep LISTEN
```

## Мониторинг ресурсов

### CPU и память

```bash
# Общая нагрузка
uptime
# 14:32:01 up 5 days, load average: 0.52, 0.48, 0.41
# load average > количество CPU = система перегружена

nproc                  # количество CPU
cat /proc/cpuinfo | grep "processor" | wc -l

# Память
free -h                # обзор памяти
cat /proc/meminfo      # подробно

# vmstat — статистика виртуальной памяти
vmstat 1 5             # обновлять каждую секунду, 5 раз
# procs ----memory---- ---swap-- -----io---- -system-- ----cpu----
# r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa
# 1  0      0 1203456 123456 2809600   0    0    12    34  100  200  3  1 95  1
```

| vmstat поле | Описание |
|-------------|----------|
| `r` | Процессы в очереди на CPU |
| `b` | Процессы в непрерываемом сне |
| `si/so` | Swap in/out (КБ/с) |
| `bi/bo` | Блочный ввод/вывод (блоков/с) |
| `in` | Прерывания в секунду |
| `cs` | Переключения контекста в секунду |
| `us/sy/id/wa` | CPU: user/system/idle/wait |

### I/O мониторинг

```bash
# iostat - статистика дисков
iostat -x 1            # расширенная, каждую секунду
iostat -x -d sda 1     # только диск sda

# iotop - как top, но для I/O
apt install iotop
iotop                  # все процессы
iotop -o               # только активные
iotop -u alice         # процессы alice
```

## Полезные однострочники

```bash
# Топ-10 процессов по CPU
ps aux --sort=-%cpu | head -11

# Топ-10 процессов по памяти
ps aux --sort=-%mem | head -11

# Найти и убить процесс по имени
kill $(pgrep nginx)
pkill -f "gunicorn"

# Подождать завершения процесса
wait $PID
tail --pid=$PID -f /dev/null   # ждать без wait

# Запустить с таймаутом
timeout 30 ./script.sh         # убить через 30 секунд

# Мониторить процесс каждые 2 секунды
watch -n 2 'ps aux | grep nginx'

# Сколько процессов у пользователя?
ps -u alice | wc -l

# Дерево родителей процесса
pstree -s -p 1234

# Найти зомби-процессы
ps aux | awk '$8=="Z"'

# Перезапустить сервис через SIGHUP
kill -HUP $(cat /run/nginx.pid)
```

## systemd и управление сервисами

В современных дистрибутивах процессы-демоны управляются через systemd.

```bash
# Основные команды
systemctl status nginx         # статус сервиса
systemctl start nginx          # запустить
systemctl stop nginx           # остановить
systemctl restart nginx        # перезапустить
systemctl reload nginx         # перечитать конфиг (SIGHUP)
systemctl enable nginx         # запускать при загрузке
systemctl disable nginx        # не запускать при загрузке

# Смотреть логи сервиса
journalctl -u nginx            # все логи
journalctl -u nginx -f         # в реальном времени
journalctl -u nginx --since "1 hour ago"
journalctl -u nginx -n 50      # последние 50 строк

# Список всех сервисов
systemctl list-units --type=service
systemctl list-units --type=service --state=running
```

## Диагностика зависших процессов

```bash
# Процесс в состоянии D (disk sleep) — проблема с I/O
ps aux | awk '$8 ~ /D/'

# Найти что блокирует
cat /proc/$PID/wchan            # в каком системном вызове застрял
strace -p $PID                  # трассировка системных вызовов

# Zombie-процессы — родитель не читает статус
ps aux | awk '$8=="Z"'
# Zombie нельзя убить — нужно убить родителя (PPID)
kill -CHLD $PPID                # попросить родителя забрать статус

# Процесс игнорирует SIGTERM?
strace -e trace=signal -p $PID  # посмотреть обработку сигналов
```
