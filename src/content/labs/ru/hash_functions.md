## Введение
Криптографическая хэш-функция - это математический алгоритм, преобразующий данные произвольной длины в строку фиксированной длины, называемую хэшем или дайджестом. Это фундаментальный примитив современной информационной безопасности. Он используется при хранении паролей, проверке целостности файлов, цифровых подписях и даже в основе технологии блокчейн.

В данной работе мы проведём сравнительное исследование трёх алгоритмов - MD5, SHA-1 и SHA-256 - как с теоретической, так и с практической точки зрения. Мы воспроизведём реальные атаки на слабые алгоритмы, продемонстрируем их уязвимости и обоснуем, почему в современных системах применяется SHA-256 и его семейство.

## Теоретическая база

### Свойства криптографической хэш-функции

Любой надёжный алгоритм хэширования должен обеспечивать несколько ключевых свойств:

- **Детерминированность** - одинаковые входные данные всегда дают одинаковый хэш.
- **Лавинный эффект** - даже изменение одного бита во входных данных полностью меняет результат хэширования.
- **Устойчивость к коллизиям** - невозможно найти два разных сообщения, которые имеют одинаковый хэш.
- **Необратимость (устойчивость к прообразу)** - по хэшу невозможно восстановить исходные данные.

### Сравнение алгоритмов хэширования

| Алгоритм | Год создания | Длина хэша | Статус | Причина устаревания |
|----------|-------------|------------|--------|---------------------|
| MD5 | 1991 | 128 бит (32 hex) | Устарел | Практические коллизии (2004) |
| SHA-1 | 1995 | 160 бит (40 hex) | Устарел | Коллизия SHAttered (2017) |
| SHA-256 | 2001 | 256 бит (64 hex) | Актуален | Коллизии не обнаружены |

## Фаза 2. Демонстрация MD5

### Шаг 3. Вычисление хэша MD5

Алгоритм MD5 был разработан в 1991 году как улучшение MD4. Изначально он широко применялся для проверки целостности данных, хранения паролей и цифровых подписей. Длина выходного значения - 128 бит.

``` md5sum data.txt ```

![04_demo_md5](/handson/images/hash_functions_sec/04_demo_md5.png)


### Шаг 4. Демонстрация лавинного эффекта

Добавим в файл один символ и снова вычислим хэш:

``` 
echo 'Test File!' > data.txt
md5sum data.txt
```

![05_md5_lavin_effect](/handson/images/hash_functions_sec/05_md5_lavin_effect.png)

Результат полностью отличается от предыдущего, несмотря на то что мы добавили лишь один символ - восклицательный знак. Это свойство называется **лавинным эффектом** и является обязательным требованием к любой надёжной хэш-функции.

### Шаг 5. Хэширование строк напрямую

Хэш можно вычислить не только для файла, но и для любой строки:

```
echo -n 'pass' | md5sum
echo -n 'pass123' | md5sum
echo -n 'Pass' | md5sum
```

![06_hash_demo_direct](/handson/images/hash_functions_sec/06_hash_demo_direct.png)

> Флаг -n важен: без него echo добавляет символ новой строки, что меняет хэш. Всегда лучше использовать **-n** при хэшировании строк.

### Шаг 6. Демонстрация уязвимости - взлом MD5 через радужные таблицы

Именно здесь проявляется главная слабость MD5: его хэши слишком коротки и хорошо изучены. Хакеры создали гигантские базы данных, **радужные таблицы**, где хэши миллионов паролей уже вычислены заранее.

Создадим файл с хэшами слабых паролей:

```
echo -n 'password' | md5sum | cut -d' ' -f1 > hashes_md5.txt
echo -n '123456' | md5sum | cut -d' ' -f1 >> hashes_md5.txt
echo -n 'qwerty' | md5sum | cut -d' ' -f1 >> hashes_md5.txt
cat hashes_md5.txt
```

![07_demo_vulnerability](/handson/images/hash_functions_sec/07_demo_vulnerability.png)

Запустим атаку по словарю с помощью **hashcat**, одного из самых мощных инструментов для восстановления паролей:

``` hashcat -m 0 -a 0 hashes_md5.txt /usr/share/wordlists/rockyou.txt ```

![08_start_attack](/handson/images/hash_functions_sec/08_start_attack.png)

![09_result](/handson/images/hash_functions_sec/09_result.png)


Альтернативно через **John the Ripper**:

```
john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hashes_md5.txt
john --format=raw-md5 --show hashes_md5.txt
```

![10_john_ripper](/handson/images/hash_functions_sec/10_john_ripper.png)

В считанные секунды hashcat восстанавливает пароли из хэшей. Это наглядно показывает, почему хранение паролей в MD5, это грубая ошибка. Алгоритм MD5 слишком быстрый: современные видеокарты способны вычислять десятки миллиардов MD5-хэшей в секунду.

### Шаг 7. Демонстрация коллизии MD5

В 2004 году исследователи публично представили первую практическую коллизию MD5 - два разных файла с одинаковым хэшем. В 2005 году атаки были улучшены настолько, что генерация коллизии стала занимать секунды.
Для демонстрации скачиваем файлы из гитхаба:

![11_download_files](/handson/images/hash_functions_sec/11_download_files.png)

![12_collision](/handson/images/hash_functions_sec/12_collision.png)

![13_collision](/handson/images/hash_functions_sec/13_collision.png)

Вывод md5sum покажет одинаковые хэши для обоих файлов, тогда как sha256sum выдаст разные. Это объясняет, почему MD5 нельзя использовать для верификации программного обеспечения или в системах безопасности.

## Фаза 3. Демонстрация SHA-1

### Шаг 8. Вычисление хэша SHA-1

Алгоритм SHA-1 был разработан АНБ США и опубликован NIST в 1995 году как ответ на недостатки MD5. Длина хэша увеличена до 160 бит. На протяжении многих лет SHA-1 считался стандартом де-факто, именно он использовался в протоколе SSL/TLS, системах контроля версий Git и сертификатах X.509.

``` sha1sum data.txt ```

![14_demo_sha1](/handson/images/hash_functions_sec/14_demo_sha1.png)

### Шаг 9. Взлом SHA-1 через hashcat

Несмотря на большую длину, SHA-1 всё равно уязвим к атаке по словарю - по той же причине, что и MD5: алгоритм создан для скорости, а не для безопасности хранения паролей.

```
echo -n 'password' | sha1sum | cut -d' ' -f1 > hashes_sha1.txt
echo -n '123456' | sha1sum | cut -d' ' -f1 >> hashes_sha1.txt

# Режим 100 = SHA-1
hashcat -m 100 -a 0 hashes_sha1.txt /usr/share/wordlists/rockyou.txt
```

![15_add_hashes](/handson/images/hash_functions_sec/15_add_hashes.png)

![16_attack1](/handson/images/hash_functions_sec/16_attack1.png)

![17_attack2](/handson/images/hash_functions_sec/17_attack2.png)

### Шаг 10. Атака SHAttered - теоретическое объяснение

В 2017 году исследователи Google и CWI Amsterdam опубликовали результаты проекта SHAttered. Им удалось впервые в истории найти практическую коллизию SHA-1.
Два PDF-файла с разным визуальным содержимым получили абсолютно одинаковый SHA-1 хэш. Это означало, что злоумышленник теоретически мог создать вредоносный документ, имеющий такой же хэш, что и легитимный - и система верификации не обнаружила бы подмену.

![18_download_files](/handson/images/hash_functions_sec/18_download_files.png)

![19_collision](/handson/images/hash_functions_sec/19_collision.png)

После этой публикации браузеры Chrome и Firefox перестали доверять TLS-сертификатам, подписанным SHA-1. Git также перешёл на SHA-256 в качестве основного алгоритма.

## Фаза 4. Демонстрация SHA-256

### Шаг 11. Вычисление хэша SHA-256

SHA-256 входит в семейство SHA-2, разработанное АНБ США и стандартизированное NIST в 2001 году. Длина хэша - 256 бит (64 шестнадцатеричных символа). На сегодняшний день ни одной практической атаки на коллизию SHA-256 не существует. Именно поэтому он является стандартом де-факто в современной криптографии.

![20_sha256_demo](/handson/images/hash_functions_sec/20_sha256_demo.png)

### Шаг 12. Итоговое сравнение всех алгоритмов

Запустим все три алгоритма для одного и того же файла и сравним результаты наглядно:

```
echo 'Cryptography Lab' > compare.txt
echo '--- Длина хэша каждого алгоритма ---'
echo -n 'MD5:    '; md5sum compare.txt | cut -d' ' -f1 | wc -c
echo -n 'SHA-1:  '; sha1sum compare.txt | cut -d' ' -f1 | wc -c
echo -n 'SHA-256:'; sha256sum compare.txt | cut -d' ' -f1 | wc -c

echo ''
echo '--- Сами хэши ---'
echo 'MD5:    '; md5sum compare.txt
echo 'SHA-1:  '; sha1sum compare.txt
echo 'SHA-256:'; sha256sum compare.txt
```

![21_compare](/handson/images/hash_functions_sec/21_compare.png)

### Шаг 13. Демонстрация лавинного эффекта

Сравниваем хэши двух паролей, отличающихся на один символ:

```
echo -n 'password123' | sha256sum
echo -n 'password124' | sha256sum
```

![22_lavin_effect](/handson/images/hash_functions_sec/22_lavin_effect.png)

## Фаза 5. Реальное применение SHA-256

### Шаг 14. Проверка целостности файлов

Одно из наиболее распространённых применений хэш-функций — верификация загруженных файлов. Любой дистрибутив Linux публикует SHA-256-хэш своих ISO-образов, чтобы пользователи могли убедиться в их подлинности.

![23_iso_test](/handson/images/hash_functions_sec/23_iso_test.png)

### Шаг 15. Современное хранение паролей

Хранить пароли в MD5 или SHA-1 недопустимо. Современные системы используют специализированные алгоритмы на основе SHA-256 с солью и большим числом итераций: bcrypt, scrypt, Argon2. Они намеренно медленные - это делает перебор паролей экономически нецелесообразным.

![24_safe_pass](/handson/images/hash_functions_sec/24_safe_pass.png)

## Итоги и выводы

### Детальное сравнение алгоритмов

| Критерий | MD5 | SHA-1 | SHA-256 |
|----------|-----|-------|---------|
| Длина хэша (биты) | 128 | 160 | 256 |
| Длина хэша (hex-символы) | 32 | 40 | 64 |
| Год создания | 1991 | 1995 | 2001 |
| Статус NIST | Не рекомендован | Не рекомендован | Активен |
| Коллизии найдены | Да (2004) | Да (2017) | Нет |
| Скорость вычисления | Очень высокая | Высокая | Умеренная |
| Взлом по словарю | Секунды | Секунды–минуты | Практически невозможен |
| Применение сегодня | Контрольные суммы файлов | Git (legacy) | TLS, Bitcoin, ОС, цифровые подписи |


### Заключение

В ходе данной практической работы была исследована работа криптографических хэш-функций MD5, SHA-1 и SHA-256. На конкретных примерах были продемонстрированы:
- Детерминированность хэш-функций: одни и те же данные всегда дают одинаковый результат.
- Лавинный эффект: изменение даже одного символа полностью меняет хэш.
- Уязвимость MD5: коллизии и взлом по словарю показывают практическую непригодность алгоритма.
- Уязвимость SHA-1: атака SHAttered (2017) доказала, что 160-битный хэш недостаточен для современных угроз.
- Надёжность SHA-256: отсутствие практических атак и операционных системах подтверждают его актуальность.

Ключевой вывод: выбор алгоритма хэширования должен определяться не его скоростью, а его криптографической стойкостью и соответствием текущим стандартам безопасности. SHA-256 (а в контексте хранения паролей - Argon2, bcrypt или scrypt) является правильным выбором для любой современной системы.
